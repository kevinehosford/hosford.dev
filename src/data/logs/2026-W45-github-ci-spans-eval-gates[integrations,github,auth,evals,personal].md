### Overview
At work: CI spans and a dashboard for the GitHub integration, and connected apps on the profile page. On matrix-actors (personal, private repo, three weeks old; 126 PRs merged this week), most of the week went into measuring the agents: gates that replay held-out tasks, and finding out where the numbers were wrong.

### Highlights
- [axiomhq/axiom#19917](https://github.com/axiomhq/axiom/pull/19917), [axiomhq/axiom#19930](https://github.com/axiomhq/axiom/pull/19930), [axiomhq/axiom#19981](https://github.com/axiomhq/axiom/pull/19981), [axiomhq/axiom#20027](https://github.com/axiomhq/axiom/pull/20027) — GitHub integration: a dashboard per linked dataset (issues, pull requests, pushes, contributors, CI), and workflow runs and jobs written as OpenTelemetry spans on edge from the webhook deliveries already being received. The spans go to events datasets and carry the installation and repository ids.
- [#10871](https://github.com/axiomhq/ctrl/pull/10871), [#10872](https://github.com/axiomhq/ctrl/pull/10872) — A "Connected apps" section on the profile page lists the MCP clients you've authorized and lets you revoke them. A grant is a consent, not a session, so it never showed in the sessions list. Also registered TanStack Start's CSRF middleware on the auth app.
- matrix-actors#368, matrix-actors#374, matrix-actors#433, matrix-actors#416 — A PR changed the planner's instructions and loosened the plan checker in the same diff, then reported the combined gain. Re-measured over 9 runs under main's checker: one wording fix held (proof refusals 15 → 3) and another PR's gain was all grader. One brief ranged from 52 to 86 across three runs. Now a PR supplies only the thing under test and main's grader scores it, and changes to the checker are gated on 16 real plans.
- matrix-actors#450, matrix-actors#466 — The first worker rollout scored 2 of 10, but six of those tasks were refused before any worker started, so it measured the harness. Refroze the set. Then eight of ten tasks ended the same way in both runs, which left the verdict resting on two. Tasks that always land or always fail get marked now, and a gate set keeps at most a third of them.
- matrix-actors#457, matrix-actors#469, matrix-actors#483 — The worker gate ran for real: a PR that changes worker instructions runs 10 held-out tasks and main runs the same 10, and the PR fails if fewer land. 6 vs 6 and 6 vs 5 passed. One came back 3 against main's 7, but five of the seven misses were workers that never started (zero turns), and the three that ran all landed, so I overrode it and recorded the cause. The gate has no noise band yet.
